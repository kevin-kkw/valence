# VALENCE: Chain Reaction — 游戏设计与 MVP 开发规格

> 版本：v0.1（2026-11-12）  
> 状态：用于 Codex 启动开发的设计草案；未经过可玩性验证  
> 类型：俯视角、自动攻击、生存、Roguelite、化学合成  
> 灵感：Brotato 的短局制生存节奏，但武器系统以原子、分子、反应为核心  
> 目标：**首先好玩；化学知识通过玩法自然习得，而非通过考试解锁。**

## 0. 给 Codex 的执行指令

请先检查当前仓库：技术栈、项目结构、已有运行方式及测试约定。**如果已有项目，尽量复用，不要为了本规格重建或换引擎。**如果是空仓库，建议使用 **Godot 4（2D）** 创建最小可玩 PC 原型；保留后续手机触控支持的架构空间，但不要一开始同时开发两端。

先实现第 1 阶段可玩垂直切片，不要试图一次完成本文件全部展望。以功能可运行、科学规则一致、数据可扩展为优先，视觉可使用几何图形与占位素材。每完成一个独立里程碑就运行/测试并报告：已完成内容、测试结果、尚未完成和发现的问题。不得把未运行的功能称为已验证。

**范围优先级：**本文件的「MVP 必须实现」优先于「后续规划」；如出现冲突，以范围和验收标准为准。未经确认的设计数值是占位建议，可在原型阶段调整并注明。

## 1. 产品定位

### 核心体验

玩家在战斗中击败敌人，获得原子；在波次之间将原子组合成分子装备；分子装备在战斗中产生物质和状态，当满足特定条件时触发化学反应与连锁伤害。玩家根据掉落资源反复改变 Build。

- 原子 = 可分配的构建资源
- 分子 = 武器 / 辅助装备
- 化学反应 = 条件满足后触发的组合效果
- 温度、点火、潮湿等 = 战场条件和状态
- 玩法目标 = 生存、击败 Boss，并通过组合探索新的 Build

**设计原则：**Chemistry IS the progression system；不出现强制知识问答。

### 不做什么

- 不做全元素周期表、不做任意分子/反应预测器。
- 不做需要玩家在战斗中手工拼接原子的操作。
- 不把核反应当化学反应；不提供真实核武器的制作或操作步骤。
- 不追求第一版化学仿真精度；只实现科学上不明显错误的、明确登记的规则。

## 2. 已讨论方向与待验证假设

| 设计项 | 状态 | 说明 |
|---|---|---|
| Brotato 式俯视角自动攻击 | 核心方向 | 玩家以移动/走位为主要即时操作 |
| 原子 → 分子 → 反应 | 核心方向 | 游戏的主差异化 |
| 波间合成与重组 | 首版提案 | 降低战斗中的操作负担 |
| 免费拆解分子并返还原子 | 首版提案 | 鼓励试错；属于游戏机制，不是现实化学反应 |
| 10 分钟左右的短局 | 首版提案 | 可调整 |
| 仅用 H、O、C 作为初期元素 | MVP 约束 | 优先验证核心闭环 |
| 六种分子武器 | MVP 约束 | H₂、O₂、H₂O、CO₂、CO、CH₄ |
| 自由画键、N/S/Cl/Fe、同位素/核能章节 | 后续规划 | MVP 暂不实现 |
| PC 先行、后续适配移动端 | 工程建议 | 依据仓库现状调整 |

## 3. 单局循环（约 9.5–10 分钟）

1. 战斗开始：玩家自动攻击最近的有效敌人，手动移动躲避。
2. 敌人被击败：掉落经验与原子资源；拾取有明确视觉反馈。
3. 波次结束：进入合成/升级界面，战斗暂停。
4. 玩家选择可合成的分子、拆解旧装备、调整装备槽，并选一个属性升级。
5. 进入下一波，敌人数量和行为难度增加；最终挑战 Boss。
6. 结算显示存活时间、伤害、反应触发、已发现分子和反应式。

**建议波次表（可调）：**

| 环节 | 时长 | 重点 |
|---|---:|---|
| Wave 1 | 60s | 基础移动与原子掉落，首次获得 H、O |
| 合成 1 | ≤30s 建议 | 首次选择 H₂ 或 H₂O |
| Wave 2 | 90s | 看到不同分子武器的效果 |
| 合成 2 | ≤30s 建议 | 获得 O₂ 的组合机会，学习供氧与点火 |
| Wave 3 | 90s | 引入 C、CH₄，出现第二种燃料路线 |
| 合成 3 | ≤30s 建议 | 重组 Build |
| Wave 4 | 90s | 更多敌人、组合链反馈 |
| 合成 4 | ≤30s 建议 | 为 Boss 调整 Build |
| Boss | 120s | 检验移动与组合策略 |

> 波间的 30s 是节奏目标，而非强制计时。MVP 可以让玩家按“开始下一波”。以上合计约 9.5 分钟，另加结算时间。

### 防止随机性卡死教程

- Wave 1 期间/结束时，确保玩家**累计得到 H×2、O×1**，并能合成 H₂ 或 H₂O。
- Wave 2 确保额外获得 O×1，使玩家能重组出 H₂ + O₂（如果选择这么做）。
- Wave 3 通过奖励或掉落确保至少有机会尝试 CH₄（C×1、H×4），可以采用保底奖励，但不得无提示凭空改变玩家库存。
- 随后原子奖励可随机化；先保证可玩路径，后调经济系统。

## 4. 操作与界面

### 战斗界面（MVP）

- 俯视角 2D 场地，WASD/方向键移动；攻击自动瞄准最近敌人。
- 初始免费装备：**电弧发射器（Arc Emitter）**，不消耗原子，提供基础伤害和点火源。
- 玩家生命、当前波次、倒计时、经验与原子库存必须可见。
- 敌人类型：普通追击、快速脆皮、缓慢高血量、Boss；几何图形占位即可。
- 必须明确区分普通攻击、气体区域、点火和燃烧爆发；优先可读性而非特效复杂度。

### 波间合成界面（MVP）

- 显示 H/O/C 原子数量，和当前装备及装备槽（建议从 3 个分子槽开始，初始电弧不占槽）。
- 显示**当前库存可合成**的分子卡片，含化学式、中文名、原子消耗、武器效果、需要的反应条件。
- 选择配方 → 立即扣除原子 → 合成分子并装备（槽满则明确提示）。
- 拆解装备 → 返还全部原子；只允许在波间进行；这是游戏规则，不是化学分解实验。
- 支持已获得分子的图鉴/说明入口；首次发现时展示分子式。
- 波间属性升级可以先用 3 选 1：移动速度、最大生命、基础攻击速度。升级系统不应阻挡核心化学循环。

## 5. MVP 元素与分子

**原子**：H（氢，通常 1 个共价键）、O（氧，通常 2 个共价键）、C（碳，常见 4 个共价键）。基础化合价提示仅用于教学，不可当作所有真实化学结构的通用判定器。

| ID | 化学式 | 名称 | 库存原子成本 | 游戏内功能（提案） |
|---|---|---|---|---|
| hydrogen | H₂ | 氢气 | H×2 | 释放短暂可燃气云；自身直接伤害低 |
| oxygen | O₂ | 氧气 | O×2 | 局部供氧辅助，强化已发生的燃烧，**不是燃料/催化剂** |
| water | H₂O | 水 | H×2 + O×1 | 自动水弹/射流，击退并施加 Wet/Cooling |
| carbon_dioxide | CO₂ | 二氧化碳 | C×1 + O×2 | 抑制局部燃烧，形成控制区域 |
| carbon_monoxide | CO | 一氧化碳 | C×1 + O×1 | 游戏化有害气体区域，产生持续伤害 |
| methane | CH₄ | 甲烷 | C×1 + H×4 | 释放可燃气云；与点火源配合造成爆发 |

**重要平衡要求：**H₂/O₂/CH₄ 等不必都能单独高输出；需要通过组合获得价值。但也不能出现玩家错误选择某个配方后完全失去战斗能力。初始电弧必须提供最低限度的持续输出。

## 6. 反应引擎：简单、可信、数据驱动

MVP 只需支持**两条燃烧反应**，其他效果是状态交互，不冒充化学反应。实现时将「化学事实」与「游戏伤害效果」分离。

### R1：氢气燃烧

`2H₂ + O₂ → 2H₂O + 能量`

- 条件：氢气云 + 氧气来源 + 点火事件。
- 战场默认存在空气（含氧），故**玩家不装备 O₂ 仍可点燃 H₂**。装备 O₂ 是供氧增强：在氧气覆盖区域内增加燃烧范围/强度，不创造“没有 O₂ 就绝不燃烧”的错误知识。
- 游戏效果：触发一次受冷却限制的范围爆发、短暂热区、水蒸气视觉效果。
- UI：首次触发显示完整、配平的反应式；后续可简化为反应名称与小图标。

### R2：甲烷燃烧

`CH₄ + 2O₂ → CO₂ + 2H₂O + 能量`

- 条件：甲烷云 + 氧气来源 + 点火事件。
- 游戏效果：不同于 H₂ 的燃烧形态（例如范围更大、点燃持续更久但冷却更长）。
- 同样可以在普通空气中燃烧，额外 O₂ 只负责加强。

### 非化学反应的状态交互

- Water/Wet：扑灭或削弱燃烧；属于水的冷却/灭火效果，不强行显示化学方程式。
- CO₂ suppression：在游戏中降低局部燃烧效果（保留“具体取决于火灾/场景条件”的现实复杂性，不做万能灭火解释）。
- Heat → Steam：表现水受热汽化时，显示为**相变**，而不是生成新物质的化学反应。

### 技术约束

- 反应触发必须有冷却、次数或区域叠加限制，避免同帧无限连锁。
- 同一物质喷射器/装备可以反复生成战场实体；**装备用的 H₂、O₂ 等分子不因每次攻击而被永久消耗**。这是明确的游戏抽象：装备是“物质发射器”，化学方程式描述产生的物质在战场上的反应，不是玩家背包原子守恒模拟。
- 反应产物不自动加入玩家背包；如产生 CO₂/H₂O 的粒子或状态，默认仅为战场效果，避免无限资源循环。
- 反应必须使用正确配平的公式；产物生成、视觉反馈、伤害、冷却是分别配置的数据。
- 如规则无法科学自洽，应降低表述力度或标明“游戏化机制”，而不是编造化学事实。

## 7. 数据组织建议

采用已有项目的原生数据资源形式（Godot Resource/JSON/其他），保持定义与玩法逻辑分离。下方为**示意结构而非强制的文件格式**：

```json
{
  "atoms": [
    { "id": "H", "name_zh": "氢" },
    { "id": "O", "name_zh": "氧" },
    { "id": "C", "name_zh": "碳" }
  ],
  "molecules": [
    {
      "id": "water",
      "formula": "H2O",
      "name_zh": "水",
      "recipe": { "H": 2, "O": 1 },
      "equipment_behavior": "water_jet"
    }
  ],
  "reactions": [
    {
      "id": "hydrogen_combustion",
      "equation": "2H2 + O2 -> 2H2O + energy",
      "requires": ["hydrogen_cloud", "oxygen_available", "ignition"],
      "effect": "hydrogen_burst",
      "cooldown_seconds": 2.0
    }
  ]
}
```

最少拆出以下概念模块：

- `AtomInventory`：库存的原子增减、合法性与显示。
- `MoleculeCatalog`：配方白名单、名称、组成、说明。
- `SynthesisSystem`：根据库存检查、合成、拆解、装备槽限制。
- `EquipmentSystem`：自动武器及物质发射器。
- `StatusFieldSystem`：气云、Wet、Heat、Ignition、OxygenBoost 等战场条件。
- `ReactionSystem`：基于白名单的反应判定、冷却、结果广播。
- `WaveDirector`：波次、敌人生成、保底资源、Boss 及结算。
- `DiscoveryLog`：首次发现的分子与反应式（MVP 可以只保存当前运行期间）。

不要求机械地创建一堆空类；以项目现有结构合理分模块即可。

## 8. 教育反馈（不能挡住游戏）

- 原子卡片始终显示符号和名称，如 `O · 氧`。
- 分子卡片同时显示 `H₂O` 和「水」；详情可看 `H×2 + O×1`。
- 首次发生化学反应，用不超过 2 秒的非阻塞浮层显示配平的反应式；不强制暂停战斗或作答。
- 首次获得新分子或触发新反应，在本局图鉴中解锁。
- 对氧气、燃烧、相变等容易误解的概念，使用简短准确的说明。

## 9. 范围划分

### MVP 必须实现

- 可运行的 PC 俯视角 2D 战斗，自动攻击、移动、血量/受伤/死亡、四类敌人（含 Boss）。
- 波次及波间合成界面，可完整开始一局并结算。
- H/O/C 库存、六种配方、制作/拆解/装备、装备槽限制。
- 六种装备各自有明确的战场行为或辅助效果。
- R1/R2 两种真实配平的燃烧反应与独立的 Wet/CO₂ 状态交互。
- 基础反应式显示、图鉴记录、最简单的声音/粒子/伤害数字反馈（可先占位）。
- 核心规则的自动化测试或可重现测试流程。

### 明确不属于 MVP

- N、Na、Cl、S、Fe、U 等更多元素与上百种分子。
- 自由画共价键、价电子或轨道模拟。
- 酸碱中和、氧化还原完整系统、物理级流体与气体扩散模拟。
- 同位素、核物理章节、核爆终局技能。
- 联机、付费、成就系统、云存档、复杂关卡、正式美术、同时发布 PC/手机。

## 10. 分阶段开发

**Milestone A — 基础战斗**

- 开始游戏、移动、初始电弧自动瞄准、敌人 AI、碰撞/扣血、敌人死亡、波次结束、死亡/胜利结算。
- 验证：可从主菜单玩到第一波结束；无脚本异常。

**Milestone B — 原子与合成**

- 原子掉落/保底奖励、库存 UI、六种合法分子配方、合成/拆解、3 装备槽、波间界面。
- 验证：库存变动正确；原子不足/槽满不能合成；反复合成拆解不复制或丢失原子。

**Milestone C — 六种分子装备**

- 六种可区分的攻击或辅助效果与战场状态。
- 验证：每种分子在实战中可被观察或量化，不是纯文字占位。

**Milestone D — 化学反应**

- R1/R2、点火、环境氧气与额外 O₂ 的区别、反应冷却、防无限连锁、反应式提示。
- 验证：无 O₂ 装备但有燃料和点火也可燃烧；有 O₂ 的燃烧有可观测增强；无点火时不应触发燃烧。

**Milestone E — 10 分钟闭环与可玩性**

- 多波、Boss、资源节奏、属性升级、图鉴、结算、性能与平衡调整。
- 验证：可完成完整一局，至少能形成 H₂ 燃烧与 CH₄ 燃烧两条不同 Build。

## 11. 验收测试（Definition of Done）

### 规则正确性

- [ ] 仅当库存包含配方所需原子时可合成；扣除正确数量。
- [ ] 拆解返还原始配方数量，不额外产出原子。
- [ ] 六个分子式的原子计数正确；未知配方不可合成。
- [ ] `2H₂ + O₂ → 2H₂O` 与 `CH₄ + 2O₂ → CO₂ + 2H₂O` 元素数两侧守恒。
- [ ] 无燃料 / 无点火不发生燃烧；默认空气存在 O₂；O₂ 装备只加强而非独占燃烧资格。
- [ ] 同一反应不得在同帧循环触发造成无上限伤害或卡死。

### 可玩性

- [ ] 能用键盘从游戏启动走到结算，无需开发者手动改配置。
- [ ] 第一波结束保证可制作 H₂ 或 H₂O。
- [ ] 玩家可以通过拆解从 H₂O 路线改成 H₂ + O₂ 路线。
- [ ] 初始电弧保证即使玩家使用纯辅助配方仍具备最低攻击能力。
- [ ] 玩家可以看见至少一次明确的燃烧 Combo 反馈与对应化学反应式。
- [ ] Boss 可被合理击败；失败后可重新开始。

### 工程质量

- [ ] 在仓库 README 中写明环境依赖、启动、测试、操作方式。
- [ ] 关键数据不散落硬编码在 UI 和敌人脚本中。
- [ ] 重要逻辑有单元测试或自动可复现的验证脚本。
- [ ] 用实际运行日志/截图/测试输出证明完成；未验证内容列为未验证。
- [ ] 不做与目标无关的重构。

### 待进行用户试玩验证的假设（不是开发完成标准）

- 90 秒内，新玩家无需教程长文即可合成第一个分子。
- 5 分钟内，大多数玩家可以理解并主动尝试燃烧组合。
- 10 分钟结束时，玩家希望再打一局尝试不同原子分配。
- 玩家自然记住 H₂、O₂、H₂O 等基本组成，而非依赖答题。

## 12. 未来方向（不要提前实现）

1. **自由拼接与化合价**：原子拥有可视化连接位，玩家自行连键；需要分子有效性检查和化学特例处理。不能用 H=1/O=2/C=4 误判一切分子。
2. **更多化学体系**：N、Cl、Na、S、Fe 等；增加酸碱、中和、氧化还原、沉淀等，但每条配方必须经过事实核查。
3. **多层次升级**：反应连锁构筑、环境条件、分子武器协同与更复杂敌人。
4. **核物理章节**：如将来引入同位素、核能等，明确其不属于化学反应。终局能力可使用非操作性、虚构化设定，不讲真实武器制作。
5. **手游适配**：虚拟摇杆、触控大按钮、手持屏的信息密度与性能优化。

## 13. 首个开发任务（Codex 从这里开始）
